# Canonicalization rules

## Stable identity

Manifest keys use names and ordinals, never `object_id`, `column_id`, `index_id`, or other instance-local identifiers.

## Columns

Column order is significant. Definitions include type schema/name, length, precision, scale, nullability, collation, identity properties, computed expression/persistence, bound default expression, rowguid, and sparse state.

## Constraint names

Explicitly named constraints are name-sensitive. System-generated names are replaced with `<SYSTEM>` in canonical definitions so equivalent autogenerated names do not cause drift.

System-named constraints receive deterministic semantic component keys derived from their type, participating columns, referenced object, or expression hash. No catalog identifier survives into the comparison key.

## Indexes

Compared properties:

- clustered/nonclustered type
- uniqueness
- disabled state
- `IGNORE_DUP_KEY`
- ordered key columns and direction
- included-column set, sorted by column name
- filter expression

Excluded physical properties include fill factor, compression, filegroups, partitioning, and online/resumable settings.

## Expressions

The collector trims surrounding whitespace but does not rewrite SQL expressions. Parentheses, comments, and internal whitespace remain significant for now. Semantic SQL normalization is deliberately deferred.
